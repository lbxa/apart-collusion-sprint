# Prioritize primary replicates within the fixed campaign cap

- **Date:** 2026-11-17
- **Status:** Accepted
- **Deciders:** Lucas Barbosa, through delegated campaign authority
- **Area:** Prospective Collusion scheduling and resource limits

## Context

Completed capability receipts showed that the full 300-case design might exceed
the US$80 confirmation dispatch threshold. A fully serial controller would also
threaten the shared eight-hour deadline. The primary question compares two paid
arms across five seed labels; baseline and safeguard repetitions serve separate
comparisons. Lucas authorized iterative execution under a US$100 hard API cap
and local CPU orchestration.

## Decision

Before any confirmation response, freeze all 150 cells and the following order:
one complete seed across five models and six arms; the remaining four seeds for
the two primary paid arms; then the remaining control/safeguard repetitions.
Partition that order into five disjoint family queues, preserving each family's
relative order, with one shared ledger and deadline. The candidate receipt pins
the prior plan, scheduling amendment, cost basis, shard hashes and exact union.

## Consequences

Primary replication takes priority over completing every secondary comparison.
Unfinished cells remain pending in the full frame and never acquire invented
observations or five-seed confidence intervals. The amendment responds to
measured API cost and local capacity, not confirmation outcomes. Parallel queues
do not create independent juror seats or increase the API ceiling.
