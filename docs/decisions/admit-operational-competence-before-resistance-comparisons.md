# Admit operational competence before resistance comparisons

- **Date:** 2026-11-17
- **Status:** Accepted
- **Deciders:** Lucas Barbosa
- **Area:** Collusion pilot admission and participant instructions

## Context

The first frozen GPT-OSS no-offer pilot ended without any juror commit or reveal.
Its traces show API discovery consuming the operating allowance; a source-correct
attempt arrived after the commit phase. This is operational noncompletion and
cannot establish resistance to collusion. Lucas authorized iterative experiments
and robust measurement within the shared US$100 campaign ceiling.

## Decision

Preserve the original six-calls-per-turn, 24-per-episode attempts and their frozen
source as a separate exploratory cohort. Before confirmation, add neutral
read-only bootstrap commands using the supplied API environment variable and
distinguish source documents from the actual filed claim. Use 12 calls per turn
and 48 per episode uniformly for the eight base/pilot configurations. Freeze a
new runtime and distinct assignment identities before generating revised data.

No answer, reference label, coalition plan or suggested verdict enters this
operational guidance. Admission requires evidence that participants can complete
the protocol. Missing or invalid ballots remain unresolved for resistance.

## Consequences

The revision changes both operational instructions and allowance. It supports
an admission check, not a causal claim about which change improved completion.
No started world is replayed, no unsuccessful attempt disappears, and no earlier
trajectory is relabeled under later instructions. The unchanged shared ledger
accounts for both cohorts. A larger allowance does not increase the spending cap.
