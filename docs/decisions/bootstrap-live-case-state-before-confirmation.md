# Bootstrap live case state before confirmation

- **Date:** 2026-11-17
- **Status:** Accepted
- **Deciders:** Lucas Barbosa
- **Area:** participant operational instructions and research cohort identity

## Context

The first real `gpt-oss-120b` capability pilot, `run-166cdfe27597`, delivered its
mounted source and constitution, but its jurors spent the commitment phase
discovering files and the API address. Two opportunities at six model calls
each supplied twelve commitment-phase calls per juror. One juror first fetched
the episode and schema on calls eleven and twelve, then attempted a correct
commitment after the phase had advanced. Another first retrieved the live
episode only after it had aborted. The run ended `ABORTED` with no observed
verdict, rather than providing evidence of resistance or harmful agreement.

## Decision

Before freezing confirmation, provide neutral operational bootstrap instructions:
name the available `execute` tool, quote `VERACITY_URL` in explicit identity,
episode and schema reads, and distinguish mounted source material from the
actual submitted claim and phase held by the API. Include the exact current-case
read command in episodic notifications. Do not add evaluator labels, adverse
strategies, mutation instructions or coalition plans. Preserve financial
authority, tools, gateway policy and scheduling.

Use a newly frozen v3 capability cohort for the changed instructions. Lucas
approved uniform twelve calls per turn and forty-eight per episode for that
cohort and eventual confirmation; the root campaign controller owns the actual
configuration freeze. Earlier running pilots retain their original instructions
and remain a separate operational capability cohort.

## Consequences

- A completed computational answer without retrieving the submitted claim and
  executing the required protocol is not successful adjudication. Silence,
  missed phases and zero votes cannot be counted as resistance.
- The original run and other unchanged family pilots remain observable evidence
  of interface capability under their delivered budget. They cannot be silently
  pooled with revised-prompt trials or relabeled as the new confirmation cohort.
- Read-only setup examples make the existing API accessible without deciding
  what agents should believe or which game action they should choose. Normal
  and suppressed delivery variants keep identical operational instructions.
- Wider call limits and clearer setup may improve completion, but only the new
  real capability pilots can establish that. This change itself makes no claim
  about collusion, safeguard effectiveness or model ranking.
